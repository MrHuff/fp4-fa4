# MXFP4 fused softmax experiments

Date: 2026-07-24

## Scope

All primary measurements use the HAO-structured TK forward kernel on GB200:

- batch 1, sequence 4096, 24 heads, Dqk/Dvo 128
- noncausal attention
- NVFP4 QK and MXFP4 PV
- 152 persistent CTAs, 512 threads per CTA
- two query stages and 512 TMEM columns
- 100 ms warmup and 500 ms measurement unless noted

The starting MXFP4 path was `0.221824 ms`, cosine `0.970392`, and RMSE
`0.006260` against Torch BF16.

## E8M0 selection

The old path emulated exact linear-domain round-to-nearest-even in log space.
Its generated scale chain contained finite and range checks, a floor
conversion, fractional reconstruction, midpoint comparison, parity handling,
and reconvergence branches.

For positive values, the nearest-power-of-two transition is
`1.5 * 2^e`. In log2 space, ignoring the exact midpoint tie rule:

```text
rounded_exponent = floor(log2_value + 1 - log2(1.5))
```

The shifted-floor implementation uses one float-to-int conversion and
branchless integer clamps. The exp2-bit alternative computes one native scalar
exp2 and extracts/rounds its FP32 exponent.

| E8M0 selector | Time (ms) | Cosine | RMSE |
|---|---:|---:|---:|
| Exact software RTE | 0.221824 | 0.970392 | 0.006260 |
| Shifted floor | **0.181856** | 0.970392 | 0.006260 |
| Exp2 plus exponent bits | 0.183040 | 0.970392 | 0.006260 |

Shifted floor is 18.0% faster than the exact path and is now the default.
Exact RTE remains available as scale selector mode 0.

An independent seed-1 check produced `0.180576 ms` for shifted floor and
`0.221472 ms` for exact RTE. Their max and mean absolute errors were identical;
cosine differed by `6e-8` and RMSE by less than `5e-10`.

Relevant static SASS changes from exact RTE to shifted floor:

| Opcode/property | Exact | Shifted floor |
|---|---:|---:|
| Total static instructions | 5,048 | 4,840 |
| `BRA` | 318 | 278 |
| `BSSY.RECONVERGENT` | 44 | 20 |
| `BSYNC.RECONVERGENT` | 44 | 20 |
| `PRMT` | 17 | 2 |
| `I2FP.F32.S32` | 16 | 8 |
| `MUFU.EX2` | 258 | 258 |

## Direct FP4 softmax experiments

Two paths classified log2 probabilities directly into E2M1 codes and formed
the denominator from the packed codes and E8M0 scale:

1. Exact threshold classification using the existing range-reduction helper.
2. A cheaper affine classifier with explicit corrections for the two
   irregular low E2M1 intervals.

The direct paths avoid elementwise `MUFU.EX2` and native E2M1 conversion, but
their integer classification and packed-code reduction cost much more.

| Path | Time (ms) | Cosine | RMSE |
|---|---:|---:|---:|
| Exact direct log code | 1.675648 | 0.970367 | 0.006201 |
| Fast affine direct log code | 0.505440 | 0.970312 | 0.006206 |
| Native exp2, quantized denominator only | 0.205824 | 0.970367 | 0.006201 |

The exact direct kernel expands to 12,624 static instructions. The fast
classifier reduces this to 7,464, but still introduces 256 scalar
float-to-int conversions and a large clamp/select network. Native
`MUFU.EX2 + F2FP.E2M1` remains substantially cheaper on GB200.

The quantized-denominator-only result shows that `PRMT + DP4A` decoding of
packed E2M1 values is also slower than the paired FP32 sum generated by nvcc.

## Scan-fused P construction

The scan-fused schedule consumes score quarter 2 first, because packed P
overlays that quarter in TMEM. It then:

1. Finds each quarter-local maximum.
2. Generates local FP4 codes before loading the next quarter.
3. Stores P into the retired score-quarter columns.
4. Selects the four E8M0 amplitudes after the row maximum is known.
5. Publishes the completed P payload and scales.

| Classifier | Time (ms) | Cosine | RMSE |
|---|---:|---:|---:|
| Exact direct, ordinary score reload | 1.675648 | 0.970367 | 0.006201 |
| Exact direct, scan fused | 2.593056 | 0.959529 | 0.007347 |
| Fast direct, ordinary score reload | 0.505440 | 0.970312 | 0.006206 |
| Fast direct, scan fused | 0.626784 | 0.959539 | 0.007345 |

Interleaving synchronous TMEM score loads, P stores, and the integer
classifier serializes the path more than eliminating four score reloads saves.
Using a local scale also loses the E8M0 rounding-residual correction and
reduces accuracy. This path remains diagnostic-only.

The selected change removes 12.5% of dynamic instructions and shortens replay
duration by 18.4%. It does not change tensor work or synchronization.

## Context

At this shape:

| Kernel | Time (ms) |
|---|---:|
| HAO BF16 | 0.164096 |
| TK shifted-floor NVFP4/MXFP4 | **0.181856** |
| HAO native NVFP4/NVFP4 | 0.192352 |
| TK NVFP4/NVFP4 | 0.194432 |
| TK exact-RTE NVFP4/MXFP4 | 0.221824 |

The shifted-floor MX kernel is 6.5% faster than the TK NVFP4 path and 18.0%
faster than its exact-RTE MX predecessor. It remains 10.8% slower than BF16.
The remaining work is still the elementwise exponentiation and FP32
denominator chain; direct FP4 classification is only useful if it can be
expressed in fewer operations than the native `MUFU + F2FP` pair.

## NVFP4 QK + FP8 PV checkpoint

The existing HAO-structured TK mixed kernel was rebuilt from the current
source and measured on the same B1/S4096/H24/D128 noncausal shape. It uses two
query stages, four K/V stages, 152 persistent CTAs, 512 threads, and all 512
TMEM columns. Q/K use NVFP4 with E4M3-per-16 scales; P and V use plain E4M3,
so PV has no P/V block-scale construction or scale-copy path.

The native HAO comparison uses the frozen upstream package whose sole source
delta initializes the otherwise-unbound `fp8_pv_p_log2_offset` to its
documented default of zero. The long-window protocol was 200 ms warmup and
1000 ms measurement with `triton.testing.do_bench` median:

| Kernel | Time (ms) | Throughput (TFLOP/s) |
|---|---:|---:|
| HAO BF16 | 0.166496 | 1,238.2 |
| HAO native NVFP4 QK + FP8 PV | **0.159744** | 1,290.6 |
| TK NVFP4 QK + FP8 PV | **0.160960** | 1,280.8 |
| TK shifted-floor NVFP4 QK + MXFP4 PV | 0.181856 | 1,134.0 |
| TK NVFP4 QK + NVFP4 PV | 0.194432 | 1,060.4 |

The TK mixed route is 3.4% faster than BF16, within 0.8% of native HAO, 11.5%
lower latency than the new MXFP4-PV route, and 17.2% lower latency than the
full-NVFP4 route. Two shorter independent-seed runs measured 0.160864 and
0.160512 ms. Output cosine was 0.989724 versus BF16 and 0.999291 versus HAO.

This result confirms that removing FP4 P-scale selection, scale publication,
and scaled PV has material value. It does not explain the full speed-of-light
gap: the 0.071648 ms fixed-P ceiling also removes the real row-max,
exponentiation, denominator, and online-softmax dependency chain. An
equivalent mixed-kernel ceiling is needed to separate those costs from E4M3 P
conversion before further softmax changes are justified.
